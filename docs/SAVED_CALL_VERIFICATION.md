# Verify one saved call record

After review, landing and deployment, the manual **Verify one saved call record** workflow runs only from reviewed `main` code. It uses the existing injected `MONITOR_API_KEY` to make one GET request to `/api/internal/operations/call-record-verification`. It requires no exported admin, database, Vapi or Twilio credentials. Before deployment, HTTP 404 is an unavailable check, never success. Do not dispatch the feature branch against production.

This is a public repository. Keep the raw Vapi UUID, business ID and per-call metadata in the private task. Prepare opaque `callRef` and `businessRef` values privately with `makeReferences(callId, businessId)` from `server/callRecordVerification.js`. Both use SHA-256; the business reference includes the high-entropy call UUID so the numeric business ID cannot be guessed from its reference alone. These references identify the target and do not replace monitor authentication. The workflow accepts only these opaque references; it prints only anonymous, closed check enums and verification booleans. It prints no references, timestamps, duration, phone numbers, transcripts or recording links.

For securely injected local automation, run `npm run verify:saved-call` with `CALL_REF`, `BUSINESS_REF`, and `MONITOR_API_KEY`. The runner has a fixed destination, rejects redirects and does not read env files. Authentication, missing endpoint, network and response-validation failures are labeled separately. It never places calls, sends messages, replays events, changes routes, clears incidents or repairs records.

The endpoint searches at most 200 recent Vapi candidates from the preceding 24 hours, plus one truncation sentinel, inside a bounded read-only, repeatable-read transaction. It matches the opaque call reference, checks global exact-provider and carrier identity counts, and verifies the call-bound business reference. A missing target in this window is unknown, not proof that no historical record exists. Truncated coverage is reported; no pagination or unbounded enumeration is available. Missing, conflicting, wrong-business, unknown or incomplete evidence never passes.

The private authenticated response contains a hash, closed check/status enums, timestamps and duration for the matching owned record only. It returns no raw IDs, names, phone numbers, transcripts, recordings, message bodies or credentials. Business mismatch suppresses saved metadata. The public runner strips even the hash, timestamps and duration before printing a result.

`savedRecordVerified: true` means one saved Vapi record for the expected business, one carrier identity, a linked caller, normal completed-call metadata, and duration agreeing with saved timestamps within two seconds. It is saved database evidence, not independent proof of live provider ownership, audio, delivery, quota correctness or overall service health. Missing carrier identity and unknown end reasons remain unverified.
